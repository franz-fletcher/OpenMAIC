# OpenMAIC

Next.js 16 (App Router, React 19, Tailwind v4) learning-content platform with a
pnpm workspace of published packages under `packages/@openmaic/*` and an
isolated Node render service. Node >= 20.9 (CI and `.nvmrc` use 22);
pnpm 10 (`packageManager` field is enforced).

## Commands

- `pnpm install` also **builds all six `@openmaic/*` packages plus the vendored
  `mathml2omml`/`pptxgenjs` forks** via `postinstall`, then copies the importer
  bundle into `public/vendor/maic-importer/`. First install is slow; that is
  normal.
- `pnpm dev` → http://localhost:3000. `pnpm build && pnpm start` for prod.
- Full CI gate, in order: `pnpm format` → `pnpm lint --fix` →
  `npx tsc --noEmit` → `pnpm check` (prettier) → `pnpm check:i18n-keys` →
  `pnpm test`.
- Single unit test: `pnpm test tests/<path>.test.ts` (vitest includes only
  `tests/**/*.test.ts` at the root).
- Per-package: `pnpm --filter @openmaic/<pkg> test` and
  `pnpm --filter @openmaic/<pkg> run typecheck`.
- E2E: `pnpm test:e2e` (Playwright on port **3002**; it boots `pnpm dev`
  itself and sets `NEXT_PUBLIC_MAIC_EDITOR_ENABLED=true`; needs
  `pnpm exec playwright install chromium`).
- Render service is **outside the pnpm workspace** with its own lockfile:
  `cd render-service && npm ci && npm test`. Excluded from root
  eslint/tsc/tsconfig.
- `packages/docs` is also excluded from the workspace (own lockfile, build,
  deploy).
- Eval runners (LLM-as-judge, not part of `pnpm test`): `pnpm eval:*` via tsx.

## Environment

- Copy `.env.example` to `.env.local`. Every provider var is optional; format
  is `{PROVIDER}_API_KEY` / `_BASE_URL` / `_MODELS`. Add new operator-facing
  vars to `.env.example` in the same PR.
- Root vitest is **hermetic: `.env.local` is NOT loaded**. Opt in per run with
  `TEST_LOAD_LOCAL_ENV=1 npx vitest run <suite>` only for live-endpoint smoke
  tests.
- Feature flags (`lib/config/feature-flags.ts`): `NEXT_PUBLIC_*` flags are
  **inlined at build time** — changing one requires restarting `pnpm dev`
  (locally) or rebuilding (CI). Server-only flags (e.g.
  `OPENMAIC_AGENT_RUNTIME_ENABLED`, which also needs `DATABASE_URL`) are
  runtime. MAIC Editor is gated by `NEXT_PUBLIC_MAIC_EDITOR_ENABLED` or
  `NEXT_PUBLIC_PRO_WORKBENCH_ENABLED`.

## Hard architecture boundaries (ESLint-enforced, errors)

- **All server-side model calls go through `callLLM`/`streamLLM` in
  `lib/ai/llm.ts`.** Never import `generateText`/`streamText` from `ai`
  directly, statically or dynamically — usage accounting, the
  `LLM_THINKING_DISABLED` kill switch, and per-provider thinking resolution
  live only in the wrapper. The bypass must be an explicit, reviewed
  `eslint-disable`.
- `@openmaic/*` package code must **never reference host-app `@/…` paths** —
  packages depend only on `@openmaic/dsl` and declared peers; the app wires
  into them, never the reverse. `@openmaic/generation` has a strict import
  allowlist (dsl, jsonrepair, katex, nanoid, partial-json, `node:`, relatives;
  no dynamic `import()` or `require()`).
- `lib/choreography` and `lib/video-export/**` must stay **pure Node**: no
  `@/…`, no react/react-dom/gsap/motion, static allowlisted imports only.
  Live app state enters video-export via injected `TimingProbe`/`AssetSource`.
- `lib/pbl/v2/operations/kernel` must not import `operations/runtime`
  (runtime depends on kernel, never the reverse).
- Root tsconfig/`npx tsc --noEmit` excludes `packages/*/src`, `e2e`, and
  `render-service` — they typecheck through their own configs.

## Published packages

All six `@openmaic/*` packages (dsl, storage, renderer, importer, generation,
editor) publish to npm. A PR touching a **publishable** file must bump that
package's `version` in the same PR or CI fails
(`scripts/check-package-version-bumps.mjs`; `docs/`, `test/`,
`vitest.config.ts` are exempt). The app consumes each package's **built
`dist/`**, so after editing package source rebuild it
(`pnpm --filter @openmaic/dsl build`) or the root app won't see the change.
Never publish manually — merged version bumps release automatically.

## Generated artifacts

- `public/vendor/maic-importer/` is copied from the importer's `dist/` by
  `scripts/sync-maic-importer.mjs` (runs in postinstall). After changing the
  importer run `pnpm sync:maic-importer`; `pnpm build` asserts it is in sync.
  `packages/@openmaic/importer/src1/` is vendored legacy code — not linted,
  not published.
- `@openmaic/renderer` generates tracked files (fonts.css, KaTeX font
  snapshots) during build. If install/build rewrites tracked files under
  `packages/@openmaic`, commit the regenerated result — CI refuses otherwise.
- Video-export font/math assets are generated by `pnpm gen:video-export-*`
  scripts.

## Testing quirks

- PostgreSQL contract suites (`*.pg.test.ts`) need a real database via
  `PG_CONTRACT_URL` + `STORAGE_PG_CONTRACT_REQUIRED=1` (CI spins a
  `postgres:16` service; see `.github/workflows/storage-pg-contract.yml`).
  Without the DB they throw rather than silently skip.
- Some vitest tests are browser-gated and only run in the CI e2e job with
  `COVER_LAYOUT_BROWSER=1` / `INTERACTIVE_STATIC_BROWSER=1`.
- Keep root `pnpm test` and `@openmaic/storage` tests sequential locally —
  running both concurrently on few cores makes 5s-timeout tests flake (known
  CI issue, avoided by design).
- `tests/lint-llm-entry-guard.test.ts` pins the LLM-import guard matrix; if
  you touch `eslint.config.mjs` boundaries, run it.

## Conventions

- Prettier: 100 cols, single quotes, trailing commas. `pnpm check` gates
  formatting; run `pnpm format` before committing.
- All user-facing UI text must be i18n keys — no hardcoded strings. Locale
  JSONs in `lib/i18n/locales/`; `en-US.json` is the source of truth and
  `pnpm check:i18n-keys` enforces key parity across all locales (no array
  values).
- Conventional Commits (`feat(scope): …`); branches `feat/`, `fix/`, `docs/`.
  Every PR must link an issue (`Closes #N`). Refactor-only PRs are not
  accepted unless a maintainer asks. AI-assisted PRs must be marked and must
  include a self-review pass (see `CONTRIBUTING.md`).
- Path alias `@/*` maps to the repo root (root tsconfig and vitest alias).
