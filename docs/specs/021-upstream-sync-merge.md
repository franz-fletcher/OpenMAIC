# 021 - Upstream Sync Merge

## Problem Statement

The OpenMAIC fork (origin: franz-fletcher/OpenMAIC) has diverged from upstream (THU-MAIC/OpenMAIC) by 216 local commits while upstream advanced 49 commits since the merge-base. The fork needs to sync with upstream to receive security fixes, new model support (GLM-5.3, DeepSeek V4), input validation hardening, and other improvements. Nine files conflict and require manual resolution.

## Solution

Merge `upstream/main` into the fork via a dedicated sync branch. Resolve all 9 conflicts by taking the union of both sides' features: the fork's RBAC/token-plan/compaction work and upstream's validation/failure-cause/new-provider work. Regenerate the lockfile after resolving the storage package.json version. Run the full CI gate to verify.

## User Stories

1. As a fork operator, I want to sync with upstream so that I receive security fixes and new model support without losing fork-specific features.
2. As a developer, I want the merge to preserve all fork features (RBAC, token-plan, compaction, MINIMAL_MODE) so that no functionality is regressed.
3. As a developer, I want the merge to preserve all upstream features (input validation, failure causes, conversation titles, Exa, GLM-5.3, DeepSeek V4) so that no upstream work is lost.
4. As a CI operator, I want the full gate to pass so that the merged code is production-ready.

## Implementation Decisions

1. **Merge strategy:** `git merge upstream/main` on a dedicated branch. NOT rebase (216 local commits make rewrite unsafe).
2. **Sync branch:** `chore/merge-upstream-2026-09` cut from main. After resolution and verification, fast-forward main and push.
3. **providers.ts timeout fix:** Take upstream's `transportFetch` wrapper over our `getLlmNoTimeoutAgent`. Upstream's approach is more robust (catches dispatcher import failure, warns once, respects caller-supplied dispatchers). Remove our `getLlmNoTimeoutAgent` function, `cachedNoTimeoutAgent` variable, and the dispatcher injection lines that reference them (the `const dispatcher = await getLlmNoTimeoutAgent()` and `const fetchInit = init ? { ...init, dispatcher } : init` lines in the OpenAI-compatible and Anthropic branches). After conflict resolution, these lines produce unused variables because `transportFetch` handles the dispatcher internally.
4. **Storage version:** Take upstream's 0.29.1 (higher published version). Do not bump further unless making additional publishable changes.
5. **Lockfile:** Regenerate with `pnpm install` after resolving package.json. Do not manually edit lockfile conflicts.
6. **stage-meta route flag:** Take upstream's `isServerPersistenceConfigured` (correct semantic gate). Our RBAC body is already auto-merged.

## Testing Decisions

1. **Unit tests:** `pnpm test` (full vitest suite) is the primary gate.
2. **Type checking:** `npx tsc --noEmit` must pass with zero errors.
3. **i18n parity:** `pnpm check:i18n-keys` must pass (locales auto-merged, verify parity).
4. **Linting:** `pnpm lint --fix` must pass (conflict resolution may introduce lint issues).
5. **Formatting:** `pnpm format` must pass.
6. **Known flake:** The database-chat-cutover 5s-timeout flake is allowed-exclusion only if it reappears. It is a pre-existing issue, not introduced by this merge.
7. **E2E:** `pnpm test:e2e` is NOT in scope for this merge verification. Unit-tier gates are sufficient. E2E can be run as a follow-up.
8. **Provider neutrality guard:** After merge, verify that the `exa` vendor debt entries (added by upstream) are correctly reflected in the auto-merged test. The fork's existing counts (qwen 24, token 5, plan 4) should be unchanged.

## Out of Scope

4. Render service changes (outside pnpm workspace, not affected by this merge).
